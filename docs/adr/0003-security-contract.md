# ADR 0003: The security contract

- Status: accepted
- Date: 2026-10-27, amended 2026-11-13
- Source: [clone-and-run plan](../CLONE-AND-RUN-PLAN.md) section 7, which states
  the contract in full, and section 17, which amends it. This record explains
  the decision and how it is built.

## Context

A markdown viewer opens untrusted files: downloaded repositories, email
attachments, AI output. Markdown previewers have shipped code-execution bugs
(Markdown Preview Enhanced had four CVEs in 2026; Typora had an RCE via a
crafted file). Remote images leak that a file was opened, and on Windows a
`file://` or UNC reference can leak credentials.

## Decision

Defense in depth, with every layer testable:

1. **No network.** The v1 binary makes no network connections. Remote
   resources referenced by a document are never loaded; the CSP `img-src`
   allows only the app's asset scheme. The webview also runs behind a
   network lock (below), complete on Windows and partial on macOS. Opt-in remote loading is a v1.1 decision
   with its own ADR.
2. **Sanitizer.** Everything that leaves `mdcore` is sanitized by ammonia.
   URL-bearing attributes are covered on every element. Links keep only
   `http`, `https`, `mailto`, fragments, and relative paths; images keep only
   local references rewritten into the asset scheme. Every `id` a document
   supplies is prefixed, so it cannot shadow one of the app's own.
3. **CSP.** `default-src 'none'`, scripts and styles only from the bundled
   app (no inline styles), no frames, objects, forms, or `base-uri`,
   `connect-src` limited to Tauri IPC.
4. **One boundary validator.** The active root is Rust-owned state, set only
   by an argv path, a Tauri drag-drop, an OS open event, or a native dialog.
   Every local reference goes through one function: raw gate, percent-decode
   exactly once, inspect (schemes, UNC and device paths, NUL) before any
   filesystem call, canonicalize, compare with the root.
5. **Navigation.** The webview never leaves the app page: link clicks are
   intercepted, the webview's own menu is suppressed on links, downloads are
   refused, and a Rust navigation handler denies everything else.
6. **IPC.** Few, narrow commands, each enrolled in the ACL and granted only to
   the main window. No command takes a trust flag or sets the root. No shell,
   filesystem, or HTTP plugin.

## How it is built

- **The ACL is opt-in in Tauri.** App commands are not checked against
  capabilities at all unless the app declares an app manifest. `build.rs`
  declares one, which also means `capabilities/main.json` cannot reference a
  command that is not enrolled: the build fails instead.
- **Asset URLs carry a hex-encoded raw reference** (`/<scope>/<hex>`), so
  the webview cannot normalise `..` segments or add a second percent-encoding
  layer. The handler undoes only the hex transport, then runs the same
  validator as the renderer, independently. It serves image types only, with
  `nosniff`, at most 20 MB each and four at a time. The scope id names the
  document's folder and root; a request for any other scope is refused.
- **Windows path forms** are inspected before the filesystem: drive-relative
  paths, alternate data streams, and reserved device names (`NUL`, `COM1`) are
  refused, because opening them reaches a device rather than a file.
- **The harness never ships.** The `test-harness` feature adds a CSP-violation
  listener (an initialization script that lives outside `ui/`), a raw-HTML
  injection command, a switch that turns the network lock off, and a stdout
  results channel. Harness commands enter the ACL only under the feature, and
  `build.rs` deletes their stale generated permission files otherwise,
  because tauri-build reads every file in `permissions/autogenerated` and
  never cleans it. CI checks the production binary for every harness marker,
  with a positive control on the harness binary.

## Amendments, 2026-11-13

An adversarial audit of the M0 code, and the tests written to answer it,
changed the contract in these ways. Each has a fixture or a unit test.

- **The network lock (Windows).** The enforcement corpus grew from one remote
  image to every way a page can ask for something, and three of them reached
  the test listener on WebView2 157 although every other layer behaved as
  designed:

  | What the page did | What stopped the page | What still reached the network |
  |---|---|---|
  | Navigated (`<meta http-equiv="refresh">`, `location`) | The Rust handler denied it; the page stayed | The request itself: WebView2 had sent it before asking |
  | `<link rel="preconnect">` | Nothing: no CSP directive governs it | A TCP connection |
  | `<iframe src>` | `frame-src 'none'`, with a report | A TCP connection, opened before the refusal |

  All three need markup the sanitizer removes, so no document could do this.
  But a layer that only holds while another holds is not a layer. The
  webview's network stack is now given nowhere to go: a proxy on the loopback
  discard port where nothing listens, no exception for loopback addresses, no
  host name resolution, and the browser's own background requests off
  (`WEBVIEW2_ARGUMENTS` in `crates/app/src/main.rs`). The app's own schemes
  are answered in-process and are unaffected. With the lock, the same three
  fixtures reach no listener.

  WKWebView takes no arguments, so on macOS the lock is the same dead proxy
  set on the webview's data store, which needs macOS 14. Measured on the
  `macos-15` runner on 2026-11-13: WKWebView does not send a request for a
  navigation the handler denies, with or without the lock; for the
  preconnect-and-frame fixture it opened two connections without the lock and
  one with it. The listener is on a loopback address, which the proxy setting
  may exempt, so whether a remote host would see that one connection is not
  known. The lock on macOS is therefore partial, and the test reports the
  count there instead of requiring zero.
- **`http` links are kept.** They were dropped, which made every link to a
  local development server dead text, and bought nothing: no link navigates
  the webview. Network-path links (`//host/x`, `\\host\x`) are dropped,
  because a browser resolves them to another host.
- **A stray `%` in a reference is a literal**, as in browsers, so `100%.png`
  works as written. Decoding is still exactly once, and it is the decoded
  string that is inspected and that reaches the filesystem.
- **The CSP lost `'unsafe-inline'` for styles and `data:` for images.**
  Nothing used either.
- **An extended allowlist, held to a table of tests.** Task-list checkboxes
  (any `<input>` is forced to a disabled checkbox), a fixed list of class
  names per element, `align` with four keyword values, prefixed ids, and
  `<picture>` with local sources only.
- **Blocked images are marked, not removed.** An image that may not load
  leaves `mdcore` as `<img src="ezmark-blocked:<reason>:<hex>">`. The scheme
  is not in the CSP, so the marker is inert even if the view layer never
  replaced it; the view layer replaces it with a line of text.
- **Context menu and downloads.** The webview's own menu on a link offers to
  save or open it, acting on a URL the document chose. The menu is suppressed
  on links, and a download handler in Rust refuses every download.
- **A root that is too broad is not adopted.** A `.git` at a filesystem root,
  or at or above the user's home directory, does not become the root.
- **The sanitizer was upgraded** from ammonia 4.2.4 to 4.2.5 for
  RUSTSEC-2026-0533, found by the dependency audit that now runs in CI.

## Evidence standard

The harness proves narrow things: a fixture's attempted loads and navigations
were stopped and reached no loopback listener, and a denied command was
rejected through the real webview IPC path. It does not prove the absence of
all outbound traffic from the process. The broader "no network" claim rests
on the CSP, on the network lock, on the app code containing no networking
calls, and on no network plugins being enabled.

A process-level measurement on Windows (`docs/measurements.md`) found one
thing outside all of that: on a machine signed in with a Microsoft account,
the WebView2 runtime contacts Microsoft about the account through Windows'
sign-in library, with or without a file open. So the contract's first line is
true of ezmark and of anything a document can cause, and is not true of the
runtime ezmark is hosted in. The README says so.

## Consequences

- READMEs with remote badges show placeholders in v1. That is the price of an
  absolute network claim.
- The network lock means the webview can never be the thing that fetches a
  remote image. Opt-in remote loading in v1.1 has to fetch in Rust.
- Every new command, attribute, or scheme is a change to this contract and
  needs a test in the matching corpus.
